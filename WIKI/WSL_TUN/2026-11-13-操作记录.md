## 3. 设置洛杉矶时区

先检查了这些值，避免只看被环境变量覆盖的 `date`：

```bash
readlink -f /etc/localtime
cat /etc/timezone
env -u TZ date '+%Y-%m-%d %H:%M:%S %Z %z'
```

当时进程的 `TZ` 已是洛杉矶，但 `/etc/localtime` 和 `/etc/timezone` 仍是上海，所以仅修改环境变量不够。

实际执行：

```bash
sudo timedatectl set-timezone America/Los_Angeles
sudo dpkg-reconfigure -f noninteractive tzdata
```

第二条用于同步 tzdata 和 `/etc/timezone`：执行 `timedatectl` 后，当时发现旧文件仍写着 `Asia/Shanghai`。已检查本机 tzdata 配置脚本会优先读取 `/etc/localtime` 指向的时区。

验证结果：

```text
/etc/localtime -> /usr/share/zoneinfo/America/Los_Angeles
/etc/timezone  -> America/Los_Angeles
当时显示：PST -0800
```

使用城市时区名称，让系统按时区数据库自动处理夏令时，不要用固定 UTC−8 代替洛杉矶时区。

## 4. 将英文设为系统和 Bash 的默认语言

最初 `LANG`、`LANGUAGE`、`LC_ALL` 只在 `xq_proxyon` 内设置，因此不开代理的新终端仍显示 `C.UTF-8`。

先执行：

```bash
locale -a
ls -l /etc/default/locale /etc/locale.conf
update-locale --help
```

本机已生成 `en_US.utf8`，不需要再次生成。`/etc/default/locale` 是指向 `../locale.conf` 的符号链接；本机的 `update-locale` 默认写 `/etc/locale.conf`。

备份后，实际通过管理员脚本调用了以下命令：

```bash
sudo update-locale LANG=en_US.UTF-8 LANGUAGE=en_US:en LC_ALL
```

最后的裸参数 `LC_ALL` 表示从默认配置中移除这个变量。最终配置为：

```ini
LANG=en_US.UTF-8
LANGUAGE=en_US:en
```

在 `~/.bashrc` 的交互式 shell 判断之后、代理函数之外加入：

```bash
export LANG="en_US.UTF-8"
export LANGUAGE="en_US:en"
```

同时移除了 `xq_proxyon` 内原有的三条语言导出语句，代理开关不再负责切换语言。

现有终端刷新方法：

```bash
unset LC_ALL
source ~/.bashrc
locale
```

验证时启动了一个不继承代理变量、初始 `LANG=C.UTF-8` 的新 Bash，未调用 `xq_proxyon`，结果为：

```text
LANG=en_US.UTF-8
LANGUAGE=en_US:en
LC_CTYPE="en_US.UTF-8"
LC_TIME="en_US.UTF-8"
其他 LC_* 分类同样继承 en_US.UTF-8
LC_ALL=
```

`LC_ALL` 留空是正确状态，不代表语言配置失败。给单个命令临时设置 `LC_ALL=C` 的能力仍然保留。

## 5. WSL 专用设置：时区、禁止 Windows 命令、保留磁盘

**这一节只适用于 WSL，不要在普通 VPS 上创建同样的 `wsl.conf`。**

最初 `/etc/wsl.conf` 中的 `timeZone=America/Los_Angeles` 不是该版本 WSL 文档列出的配置项，已移除并改为关闭 Windows 时区同步。后来又增加了互操作和磁盘挂载设置。

最终 `/etc/wsl.conf`：

```ini
[boot]
systemd=true

[user]
default=chris

[time]
useWindowsTimezone=false

[interop]
enabled=false
appendWindowsPath=false

[automount]
enabled=true
root=/mnt/
```

效果：

- Linux 自己管理时区。
- 禁止 WSL 启动 Windows 程序，并停止自动加入 Windows PATH。
- 保留 Windows 固定磁盘自动挂载。本机有 `/mnt/c`、`/mnt/d`、`/mnt/e`；它不是只允许 D/E 的白名单。
- 宿主机 HTTP 代理通过 TCP 连接使用，不依赖启动 Windows 程序。

今天用提权的 Python 脚本备份、合并并校验了配置，未用新文件覆盖用户、systemd、时区等原设置。另一套 WSL 可用 `sudoedit /etc/wsl.conf` 合并相同字段，用户名应按实际修改。

保存工作后，**在 Windows PowerShell 中执行**，不能当作 Linux 命令运行：

```powershell
wsl --terminate Ubuntu
```

再重新打开 Ubuntu。也讨论过 `wsl --shutdown`，但它会关闭所有 WSL 发行版；只重启 Ubuntu 时优先使用上面的命令。

配置写入和解析已经验证；Codex、Claude Code、Node 已通过移除 Windows PATH 后的启动检查。重启后是否真正禁止 Windows 程序启动，需要在目标环境再核对，不能把配置已保存等同于已完成重启验证。

重启后的只读检查：

```bash
cat /etc/wsl.conf
printf '%s\n' "$PATH" | tr ':' '\n'
if [ -f /proc/sys/fs/binfmt_misc/WSLInterop ]; then
    cat /proc/sys/fs/binfmt_misc/WSLInterop
fi
findmnt /mnt/c
findmnt /mnt/d
findmnt /mnt/e
codex --version
claude --version
```

Windows PATH 不应再自动注入。**复查更正：不能用 `WSLInterop` 注册项必须消失或禁用作为判断标准。** WSL2 的 binfmt 处理器可能在整个 VM 层面保持注册，而本发行版的互操作权限由 `/etc/wsl.conf` 和发行版 interop 通道控制；环境变量或套接字是否存在也不是单独的完整证明。应结合配置、发行版重启时间和环境检查判断。本次没有运行 Windows 程序做实际执行测试。浏览器自动打开、`explorer.exe`、`clip.exe` 等相关功能会受影响，登录时可手动把 URL 复制到浏览器。详见 [复查报告](2026-11-13-复查报告.md) 和 [微软互操作技术说明](https://wsl.dev/technical-documentation/interop/)。

## 6. WSL 代理开关与最终输出

本节记录的是**全流量 TUN 部署前的环境变量版**。后来已升级为全 WSL 网络层开关，当前使用和配套服务以 [全流量部署记录](WSL-全流量代理部署记录.md) 为准。

最终行为：

- 默认代理端口 `16791`，`xq_proxyon 端口` 可以覆盖。
- 通过 IPv4 默认路由取得本机 WSL NAT 网关，作为 Windows 宿主机代理地址。
- 验证端口范围 1–65535，错误参数不会修改已有代理变量。
- 开启时设置大小写 HTTP/HTTPS/ALL_PROXY 和 NO_PROXY；关闭时清除这八个变量。
- 开关都显示状态、WSL IP、宿主机 IP、代理 IP/端口、公网出口 IP 和连接验证结果。
- 按最终要求，只去掉“连接对端 IP”这一行，其他输出保留；内部仍使用连接对端检查是否经过代理。
- 公网 IP 首先查询 `https://api.ipify.org`，失败后回退到 `https://icanhazip.com`；每个服务最多等待 8 秒。

使用：

```bash
source ~/.bashrc

# 或自定义端口：xq_proxyon 16791
xq_proxyoff
```

> 2026-11-14 注：本节是 TUN 方案之前的环境变量版本，仅作历史记录，新机器不要执行。`~/.config/xq/proxy.bash` 和对应的 `.bashrc` 加载行会让 TUN 首次安装器 `install.py` 拒绝安装；文件现位于 `WIKI/WSL_TUN/scripts/`。

如果要在另一套类似 NAT 网络的 WSL 使用导出的函数，可把文件复制到用户配置目录，再在 `.bashrc` 中加载一次：

```bash
mkdir -p "$HOME/.config/xq"
cp "$HOME/WIKI/scripts/xq-proxy-wsl-env-legacy.bash" "$HOME/.config/xq/proxy.bash"
```

在 `.bashrc` 中加入一次，并删除或替换同名旧函数，避免重复定义：

```bash
if [ -f "$HOME/.config/xq/proxy.bash" ]; then
    . "$HOME/.config/xq/proxy.bash"
fi
```

只加载函数不会自动开启代理。HTTP 代理环境变量只影响读取这些变量的程序，不能当作整台机器的全局代理。普通 VPS 没有 Windows 网关，改用 [VPS 指南](VPS-复现指南.md) 中的显式代理地址。

```bash

```

根据后台服务启动时间和启动警告的保存方式，判断需要重启后台服务。诊断中尝试读取新连接的警告通知没有完成初始化，因此不把该尝试当作缓存原因的直接验证。

用户应在 **退出 Codex 后的普通 WSL/Linux 终端** 执行：

```bash

codex resume --last
```

涉及模型窗口、MCP 密钥等新默认配置时，重启后新建会话更便于确认新配置已加载。后台服务重启会中断它承载的会话，不应让正在运行的助手自行重启自己的宿主进程。本次记录没有声称这些重启命令已由助手执行。


这允许把额外权限申请交给用户审批，并不替代 Linux 的 `sudo` 权限。在 VPS 上是否需要这样设置，取决于其 Codex 版本、运行方式和管理策略。
